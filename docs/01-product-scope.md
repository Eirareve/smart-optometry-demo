# 产品范围

## 为什么做

最终产品方向是“智能验光仓”。在真实设备接口资料尚未取得的阶段，先通过浏览器中的网页 Demo 验证产品形态、设备控制流程、检测状态、数据呈现和报告交互，为后续真实设备接入建立清晰边界。

## 当前阶段

当前阶段为 **V0.1 网页 Demo**。React 基础工程、首页、`DeviceAdapter` 抽象契约、Mock Device、ExamService 和模拟验光进行页已经实现；结果页和报告页尚未实现，也没有接入真实设备。

V0.1 的目标闭环为：

```text
进入系统
  → 查看设备状态
  → 开始智能验光
  → 模拟设备准备
  → 模拟左眼采集
  → 模拟右眼采集
  → 模拟数据分析
  → 查看验光结果
  → 查看 17 项扩展指标
  → 查看电子验光报告
  → 重新检测
```

## 当前解决什么

- 展示智能医疗设备控制台的产品形态。
- 验证完整、可理解的验光交互流程。
- 规划设备状态、异常状态、空数据状态和取消流程。
- 展示 Demo 用 SPH、CYL、AXIS 数据。
- 使用 `metric_01`～`metric_17` 展示 17 项未知扩展指标的占位位置。
- 建立 UI、验光流程服务与设备适配层解耦的架构约束。
- 为未来替换 Mock 数据源、接入真实设备预留边界。

## 当前不解决什么

- 真实硬件通讯及厂家 SDK、DLL、USB、串口、TCP 或私有协议接入。
- 17 项数据的真实字段定义、医学名称、单位、范围或临床意义。
- AI 医疗诊断、疾病判断及处方能力。
- 3D 人脸扫描、数字人、镜框推荐、虚拟试戴和瞳高二次扫描。
- 镜片加工、商品、库存、订单和支付。
- 复杂用户权限及 HIS/EMR 等医疗系统正式集成。
- 生产环境部署、运行监控和正式合规方案。

## 数据与声明边界

- Demo 数据必须是合成或模拟数据，并在界面和报告中明确标记。
- 模拟数据不得用于医疗诊断或处方。
- 除 SPH、CYL、AXIS 外，不为未知字段赋予医学含义。
- 未确认的 17 项统一表示为“扩展检测指标 01”～“扩展检测指标 17”。
